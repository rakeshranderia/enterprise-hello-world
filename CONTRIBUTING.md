# Contributing

This repository is primarily a delivery-method demonstration, but changes should still follow a controlled workflow.

## Branching

Create a short-lived branch from `main`.

Examples:

```text
feature/add-health-endpoint
bugfix/hello-world-typo
docs/update-runbook
```

## Change Flow

1. Create or reference an issue.
2. Create a branch.
3. Make the change.
4. Run tests locally.
5. Push the branch.
6. Open a pull request.
7. Allow CI to run.
8. Review the change.
9. Merge after required checks pass.
10. Close the linked issue.

## Commit Messages

Use short, descriptive messages.

Examples:

```text
Add health endpoint
Fix Hello World response typo
Update cutover validation steps
```

Avoid manufactured history or meaningless commits.
