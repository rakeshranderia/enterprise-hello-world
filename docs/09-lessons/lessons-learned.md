# Lessons Learned

## 1. Simple Code Can Still Need Good Delivery

Application complexity and delivery discipline are different things.

## 2. Requirements Should Be Testable

`Hello World` is trivial, but it is still an explicit acceptance criterion.

## 3. Tests Protect Requirements

A test that simply changes whenever implementation changes is weak.

## 4. CI Creates Fast Feedback

Automated validation reduces the chance that obvious defects reach release.

## 5. IaC Makes Desired State Reviewable

The Bicep example demonstrates that infrastructure can be versioned and validated like application code.

## 6. Go-Live Is Not the End

Hypercare, operational acceptance and BAU handover matter.

## 7. Incidents Need Communication and Evidence

Even a tiny simulated incident can demonstrate ownership, decisions, recovery and learning.

## 8. Documentation Is Part of the Product

A service is easier to operate when requirements, architecture, release and recovery information live with the code.

## Final Principle

**The application is intentionally simple. The operating model around it is the demonstration.**
